# Engraving Algorithm Audit

*Decision document — supersedes the current ETF + line-screen approach. Status: recommended for adoption. Reviewer score 7.5/10, recommendation sound.*

---

## 0. Executive summary (the one decision)

The current filter reads as "a layer of imprint over the image" for a single architectural reason: **its line geometry is generated by a global, screen-space sine screen and only *masked* by image tone.** The stripe phase is `dot(gl_FragCoord.xy, dir)/spacing` — a function of absolute canvas position, not of the subject — so lines can never become continuous integral curves of the form. Re-parameterizing this shader cannot fix it; the missing primitive is **the streamline (a line with identity: a start, a path, an end).**

**The decision:** replace the per-pixel threshold screen with a **flow-guided line-placement renderer** built on the ETF field we already compute. Two-tier execution:

- **Render-on-release (CPU/Worker):** tone prep → ETF → FDoG edges → **edge-terminated, evenly-spaced streamline placement (Jobard–Lefer) with intra-band anti-lattice jitter**, separation driven by tone → stroke geometry buffers.
- **Real-time (GPU):** stroke rasterization, duotone, paper grain, all cosmetic sliders at 60 fps.

Keep the ETF math. Throw away the 4-angle sinusoidal screen, the `carve` floor, and the Density/Frequency/Direction/Thickness/Follow-form parameter model.

**One caveat stated up front (it shapes the whole design):** streamline placement does *not* defeat the overlay look "for free." Jobard–Lefer is a uniform-separation algorithm; a constant `d_sep` across a flat midtone produces a perceivable parallel lattice — the literal overlay signature. The rewrite earns its result only by adding three things the base algorithm does not provide: **(a) intra-band stochastic spacing/phase jitter, (b) FDoG-edge termination of streamlines, and (c) region-based (piecewise) orientation for planar subjects.** These are first-class pipeline steps below, not polish.

## 1. What we want to achieve

**Goal:** Natively re-render a photo's tone and structure *into engraving line work* — steel-plate intaglio / banknote-portrait look — where the lines themselves describe the subject. Three locked reference looks and presets: **Building / Architectural** (green ink, piecewise-planar diagonal hatch), **Portrait** (sepia, contour hatch + stipple + cross-hatch mesh), **Cube / Sculptural** (rose, flowing contour lines).

**Target-look rubric (distilled).** An output is "engraving-grade" only if **all Core traits pass**:

| # | Core trait | Failure = overlay |
|---|---|---|
| 1 | **Lines follow form** — orientation locally derived from structure (ETF or region-planar), not a global angle | constant angle in flat regions |
| 2 | **Tone = line modulation, not opacity** — darkness from spacing/width/layer-count; every line full-ink | grey/faded lines |
| 3 | **Bare-paper highlights** — brightest regions carry *zero* ink (tinted paper, never #fff) | faint ink wash in highlights |
| 4 | **Continuous coherent strokes** — long engraved cuts, not per-pixel dashes | sine-threshold "ropes" |
| 5 | **Variable line weight (swell)** — burin lozenge; thickness swells/tapers along length | uniform machine-rule width |
| 6 | **No visible uniform grid** — no *rigid, sharp-peaked* periodic lattice in flat/midtone areas | perceivable rigid pitch lattice |
| 7 | **Edges break/redirect lines** at boundaries (by *geometric termination*, not masking) | hatch slides across silhouettes unbroken |

Secondary "premium" traits (graded): layered cross-hatch only in shadow; lozenge mesh in deep shadow; stipple accents (engraved line-end flicks) in transitions; distinct contour-emphasis lines; flow continuity (combing); strict duotone; clean density *termination*.

**Per-reference dominance:**

| Trait | Building | Portrait | Cube |
|---|---|---|---|
| Follow-form | planar (piecewise, region-based) | contour (ETF) | curvature (ETF, purest) |
| Edge breaks | **dominant** | medium | minimal |
| Line swell | low | **high** | medium |
| Cross-hatch | sparse | **mesh, layered** | sparse |
| Stipple | none | **yes** | none |
| Flow smoothness | piecewise | medium | **dominant** |
| Bare-paper highlights | medium | **high** | **high** |

The portrait is the hardest case (smooth skin exposes any screen *and* is the worst case for stroke count); the cube is the purest test of flow continuity on smooth gradients.

## 2. Why the current implementation reads as an overlay (root causes)

Audited files: `src/engine/orientation.ts`, `src/engine/shaders.ts`, `src/engine/EngraverRenderer.ts`, `src/engine/presets.ts`, `src/types.ts`.

**The one-line diagnosis:** the engine rotates a *globally-ruled, screen-space sine screen* per pixel and inks it by darkness. Because the stripe phase is `dot(gl_FragCoord.xy, dir)/spacing` with a constant coverage floor, and the flow field only *tilts* that global ruling, the lines never become continuous integral curves of the form.

Concrete root causes, in priority order:

1. **Stripe coordinate is global screen space, not the form (the single biggest cause).** `vec2 p = gl_FragCoord.xy` with `u = dot(p, d)/spacing`. Phase is a function of *absolute pixel position on the canvas*. Rotating `base` per pixel slices a single global plane wave at varying angles → forking/swirling/discontinuous stripes near curvature. **There is no line integration / no flow-aligned phase accumulation anywhere.**

2. **Tone drives coverage, not line structure.** Darkness becomes a `base_cov` scalar and per-layer `smoothstep` gates; `layerInk` inks where `cov > screenVal`. Line placement, count, and path never come from the image — they come from `spacing` and `gl_FragCoord`.

3. **The `carve` floor paints the screen everywhere.** `carve = 0.16 * smoothstep(0.02, 0.20, d)` adds a constant coverage floor across every non-highlight pixel — the literal definition of an overlay.

4. **Per-pixel direction with no rendered-line coherence.** The shader re-derives `base` independently per fragment and feeds a *global* plane wave. Adjacent fragments sample *different global rulings*, so neighboring inked pixels don't lie on a shared continuous line.

5. **Orientation field too coarse, and the encoding cancels under interpolation.** Field at ≤360px stretched with `LINEAR` over up-to-2400px. The stored value is the **tangent vector components**, so `LINEAR` does a *vector* lerp. The real failure is the **head–tail ambiguity**: `+t` and `−t` encode the same orientation, so neighboring texels that disagree on sign lerp to **near-zero length** → trips `defined→0` → `u_follow` off across smooth areas → fall back to the **fixed global angle**, the most overlay-like behavior, exactly where it fails worst.

6. **Contours are a thresholded magnitude, not traced lines.** Ink where `edgeMag` crosses a smoothstep band → fat, fuzzy blobs, no FDoG/NMS/thinning, and they never *break* the hatch.

**Parameter verdict.** The user's instinct is right. Density / Frequency / Direction / Thickness / Follow-form parameterize a *screen generator*, not an engraving. Only tone remap and duotone survive as meaningful and orthogonal.

## 3. The recommended NATIVE algorithm pipeline

**Winner: a layered, flow-guided line-placement renderer** — ETF backbone (keep) + **evenly-spaced streamlines with tone-driven separation (Jobard–Lefer), edge-terminated and jitter-broken** as the primary tonal engine + **Flow-XDoG / FDoG** for contours, accents, and stroke termination. This is the only family that makes tone *from adaptive spacing of opaque strokes*, so no fixed carrier pattern can appear.

**Why this and not the alternatives:**

- **Streamlines (Jobard–Lefer)** — tone = line spacing by construction; vector-native; the most intaglio-authentic. ([Jobard & Lefer 1997](https://link.springer.com/chapter/10.1007/978-3-7091-6876-9_5) · [vpype-flow-imager](https://github.com/serycjon/vpype-flow-imager))
- **Coherent Line Drawing ETF + FDoG** — form-following backbone + genuine contour extractor; we keep the ETF we already compute. ([Kang et al. NPAR 2007](https://cg.postech.ac.kr/papers/kang_npar07_hi.pdf))
- **XDoG** — re-maps tone into ink with a tanh soft-threshold; crisp boundary lines without a carrier. ([Winnemöller CAG 2012](https://users.cs.northwestern.edu/~sco590/winnemoeller-cag2012.pdf))
- **Rejected as the *primary* engine:** Rosin & Lai warped-dither ([arXiv 2008.05336](https://arxiv.org/pdf/2008.05336)) and warped line-screen remain per-pixel threshold ops (lattice risk) — we adopt their form-warp idea on streamlines, not tiles. **TAM** ([Hoppe](https://hhoppe.com/proj/hatching/)) and **plain LIC** ([Wikipedia](https://en.wikipedia.org/wiki/Line_integral_convolution)) are tile-blend/overlay-like and demoted to optional faint sub-tone.

**Data flow:**

```
[GPU — field passes, read back once per recompute]
  decode → luminance → tone transfer (blackPoint/highlightClip/gamma) → quantize to tonalLevels
  → structure tensor → ETF smoothing (Kang) ......... orientation tensor (sin2θ/cos2θ)
  → FDoG (Kang/Winnemöller) ......................... coherent contour + edge map
  → GPU→CPU readback: orientation tensor, edge map, tone map

[CPU / Web Worker — render-on-release, owns all stateful geometry]
  → build oriented field:
        Portrait/Cube: lerp(fixedAngle(baseAngle), ETF, flowWeight)
        Building:      REGION-PLANAR orientation (§3.2), not a global angle
  → Jobard–Lefer streamline placement, d_sep = f(local tone)  ... PRIMARY HATCH
       · spatial-hash min-distance test; RK2 advance along field
       · ANTI-LATTICE: per-seed phase jitter + per-band d_sep dither (§3.1)
       · TERMINATE on: FDoG edge crossing, proximity, low-flow, domain exit (§3.3)
  → cross-hatch: 2nd/3rd streamline sets on the LOCALLY-rotated field, gated to dark bands
  → stroke realization: per-sample width = strokeWidth·(1+swell·(darkness−0.5)); end taper;
       lightest active band → tapered line-END FLICKS (stippleTransition)
  → emit stroke vertex buffers (+ optional SVG polylines for export)

[GPU — real-time, every frame]
  rasterize strokes (instanced quads / SDF) with AA → contour composite → duotone + grain + bleed
```

The decisive change: **tone is created by spacing, placement, and termination of opaque lines, not by coverage-modulated opacity of a stacked sine screen.**

### 3.1 Anti-lattice (NOT free from the base algorithm)
Plain JL with constant `d_sep` over a flat midtone yields a sharp single-peak lattice (overlay tell C2/C6). Break it *within each tonal band*: per-seed blue-noise **phase jitter** (±`latticeJitter`·`d_sep`); per-band **`d_sep` dithering**; **stochastic stroke-length breakup**. Intended signature: a **broadened anisotropic band**, never a sharp delta peak. `latticeJitter` default 0.35.

### 3.2 Region-planar orientation (Building)
Cluster the orientation histogram (circular k-means on 2θ, k=3–6) into dominant planar angles; each connected region gets its own locally-constant angle. `flowWeight` blends **region angle ↔ ETF**, never a single global vector. Gated by `planarRegions`.

### 3.3 Edge-terminated streamlines (by geometry, not masking)
JL advection halts when a streamline crosses/comes within `edgeBreakDist` of an FDoG edge; seeds don't cross edges from their parent. Lines *stop* at boundaries; the contour layer draws the boundary. Masking only cleans sub-pixel residue.

## 4. The new PARAMETER MODEL

Split into **Structure** (forces a render-on-release recompute) and **Style** (real-time GPU). Minimal, orthogonal. Presets are saved points in this space.

### Tone (Structure)
| Param | Meaning | Range | Default |
|---|---|---|---|
| `tonalLevels` | Posterization steps before line placement | 3–12 | 6 |
| `blackPoint` | Luminance mapping to full ink | 0.0–0.4 | 0.08 |
| `highlightClip` | Luminance above which = bare paper | 0.6–1.0 | 0.92 |
| `gamma` | Midtone bias | 0.5–2.0 | 1.0 |

### Line geometry (Structure)
| Param | Meaning | Range | Default |
|---|---|---|---|
| `basePitch` | Mid-band line spacing (px @ field res) | 2–16 | 6 |
| `spacingRatio` | Darkest:lightest spacing ratio (tonal contrast) | 2–10 | 5 |
| `strokeWidth` | Base ink width (px) | 0.4–2.0 | 0.9 |
| `swell` | Width variation by tone (burin swell) | 0.0–1.0 | 0.5 |
| `latticeJitter` | Anti-lattice spacing/phase break-up | 0.0–1.0 | 0.35 |

**Tone→separation:** per band `i`, darkness `t_i∈[0,1]`: `d_sep(i) = basePitch · spacingRatio^(−t_i)`; placed at `d_sep·(1+latticeJitter·ξ)` with blue-noise `ξ`; seed phase offset `blueNoise·latticeJitter·d_sep`. Bands above `highlightClip` place **zero** lines.

### Direction & structure (Structure)
| Param | Meaning | Range | Default |
|---|---|---|---|
| `flowWeight` | Region/fixed-angle ↔ ETF blend | 0.0–1.0 | 0.7 |
| `baseAngle` | Fixed angle (°) — only when `planarRegions` off | 0–180 | 35 |
| `planarRegions` | Region-planar (Building) vs ETF (Portrait/Cube) | bool | false |
| `flowSmoothness` | ETF coherence/sweep + mean stroke length | 0.0–1.0 | 0.6 |

### Layering & transitions (Structure)
| Param | Meaning | Range | Default |
|---|---|---|---|
| `crossHatch` | Layers + engagement (local tangent rotated, not global) | 0.0–1.0 | 0.4 |
| `stippleTransition` | Lightest band → tapered line-END flicks | 0.0–1.0 | 0.5 |
| `edgeStrength` | FDoG contour reinforcement | 0.0–1.0 | 0.4 |
| `edgeBreakDist` | Streamline termination distance near edges (px) | 0.5–4.0 | 1.5 |

### Duotone (Style — real-time)
| Param | Meaning | Range | Default |
|---|---|---|---|
| `inkColor` | Line color | hex | `#1f5c3a` |
| `paperColor` | Background tint | hex | `#efe9d8` |

**Stipple is committed to line-end taper flicks; random dashing is dropped.** Cross-hatch/stipple are 0–1 macros; advanced sub-thresholds live in a drawer.

**Three presets as points:**

| | Building | Portrait | Cube |
|---|---|---|---|
| `tonalLevels` | 5 | 9 | 4 |
| `planarRegions` | **true** | false | false |
| `flowWeight` | 0.5 (region↔ETF) | 0.85 | **0.9** |
| `flowSmoothness` | 0.4 | 0.7 | 0.85 |
| `latticeJitter` | 0.3 | 0.4 | 0.25 |
| `crossHatch` | 0.25 | **0.8** | 0.1 |
| `stippleTransition` | 0.2 | **0.7** | 0.4 |
| `edgeStrength` | **0.6** | 0.45 | 0.7 |
| `edgeBreakDist` | **1.0** | 1.5 | 2.5 |
| `swell` | 0.3 | 0.6 | 0.7 |
| ink / paper | green / cream | sepia / warm grey | rose / blush |

Cube uses `flowWeight 0.9` + high `flowSmoothness` (raw ETF is noisiest on flat-shaded faces). Reachability of all three looks is a **Phase-1 validation gate**, not assumed.

## 5. In-browser implementation architecture

**Hybrid GPU-field + CPU-geometry, render-on-release for structural stages.** A pure-GPU fragment stack *cannot* do evenly-spaced streamline placement (needs global mutable state + sequential seeding) — staying pure-GPU is what keeps you trapped in line-screens.

Field passes (tensor, ETF, FDoG) on **GPU** (stateless ping-pong FBOs); streamline placement + geometry in a **CPU Web Worker**; bridge = **one GPU→CPU readback per recompute** of three small textures at ≤1536px.

| Stage | Engine | Cadence |
|---|---|---|
| Decode + luminance + tone simplify | GPU | real-time |
| Structure tensor + ETF | GPU FBO | on recompute |
| FDoG edges | GPU multipass | on recompute |
| Readback (tensor, edge, tone) | bridge | on recompute (~5–15 ms) |
| **Streamline placement (Jobard–Lefer)** | **Worker** | **render-on-release** (~400 lines TS) |
| Stroke density/width, cross-hatch | Worker | render-on-release |
| Composite: raster, duotone, grain | GPU | real-time |

Field + streamlines at ≤1536px; strokes rasterized at full canvas res (vector scales cleanly). Worker returns `Transferable` buffers; structure recompute debounced 150–300 ms with cancellation. During a structure drag, show a cheap GPU streamline-screen **proxy** (draft); swap to real placement on release.

**Libraries:** `regl` for multipass GPU; hand-written GLSL (tensor/ETF/FDoG); hand-written TS JL in the worker (seed queue + uniform spatial grid; RK2; blue-noise). OpenCV.js optional/default-off. SVG polylines on demand for export.

**Performance (target, validate in Phase 1):** field ~30–80 ms + readback ~5–15 ms (offline); placement scales with stroke-sample count — **Portrait worst case ~50–250 ms** (binding constraint, per-band sample budget enforced); raster+duotone ~3–8 ms/frame → 60 fps for style sliders.

## 6. Phased migration plan

**Keep:** ETF math in `orientation.ts` (consumer + encoding change, not core); tone/duotone; `presets.ts` three-preset shape.
**Replace:** the 4-angle sine shader; the `carve` floor; the `smoothstep(edgeMag)` blob; the Density/Frequency/Direction/Thickness/Follow-form model.

- **Phase 0 — Field hardening (low risk, immediate).** Store/interpolate orientation as a **director tensor (sin2θ, cos2θ)** so `LINEAR` can't sign-cancel tangents to zero (root cause #5). Raise field res to ~1280–1536px. Remove the `defined→0` collapse. Removes the worst overlay behavior before any rewrite.
- **Phase 1 — Worker + streamline core + anti-lattice + validation gate.** Web Worker; tone-prep + quantization; JL placement with explicit tone→`d_sep` and §3.1 anti-lattice from the start. New GPU stroke path behind a feature flag, A/B vs old shader. Gate: measure Portrait worst case + confirm three looks reachable.
- **Phase 2 — Stroke realization + new params + edge termination.** Swell, end-taper, line-end flicks; wire FDoG edges into JL termination (§3.3); land the 16-param model + Structure/Style UI split; remove old sliders.
- **Phase 3 — Edges, cross-hatch, region-planar.** FDoG contour lines; local-rotated cross-hatch sets gated to dark bands; region-planar path behind `planarRegions` for Building.
- **Phase 4 — Presets + polish.** Re-fit presets against reference renders; paper grain / ink bleed / multiply-at-intersection; SVG export.
- **Phase 5 — Cleanup.** Delete `carve`, global-screen `screenVal`/`layerInk`, dead plumbing.

## 7. Risks, open questions, and overlay-failure detection

**Risks:** placement performance on dense darks (per-band sample budget); flow singularities on smooth surfaces (strong ETF smoothing + 10% fixed component); anti-lattice over-correction (bounded blue-noise); worker marshaling (Transferables + debounce); cross-hatch muddiness (translucent ink + multiply, cap layers); region-planar instability (hysteresis + min area).

**Open questions:** face/landmark warp for portrait (ship ETF-only first); vector export vs raster parity; optimal region-cluster `k`.

**Overlay regression gate (score per region):** primary gate **C1 + C2 + C4 together**; any one in a flat midtone = fail.
- **Lattice (C2/C6):** FFT a flat patch; fail only on a **sharp, high-Q, narrow-band peak**. Jittered streamlines give a broadened anisotropic band (pass). `latticeJitter=0` should fail; raising it moves fail→pass.
- **Partial-opacity tone (C3):** ink-opacity histogram; partial-opacity mass = fail (new pipeline passes — opaque only).
- **Bare-paper highlights (C9):** patches above `highlightClip` must be zero-ink.
- **Global-angle (C1):** orientation histogram in flat regions; one global bin = fail; region-planar must show several local bins.
- **Edge-breaking (C5):** stroke continuity across FDoG edges; strokes crossing above a small count = fail.

"By construction" the pipeline gets only: **no partial-opacity tone (C3), zero ink in highlights (C9), no fixed-screen carrier.** It earns C1, C2/C6, C5 via §3.2, §3.1, §3.3 respectively.
